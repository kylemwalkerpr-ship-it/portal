# Payhip Product Quality + SEO Funnel Audit

Status: ACTIVE AUDIT
Branch: `audit/payhip-product-quality-funnel`

## Operating rule

1. **Opera Browser is the primary authenticated browser** for Payhip seller-side inspection because it is faster and already carries the working Payhip session.
2. **TinyFish is reserved for research where it adds material advantage**: keyword research, SERP analysis, competitor analysis, content-gap research, current official-source verification, search intent, and conversion-funnel research.
3. No product is promoted until the **actual buyer deliverable has been opened and validated**. File size alone is never a pass/fail test.
4. Raw authoring/source files such as `.md` are not acceptable as the paid deliverable unless the listing explicitly sells source text and the files are genuinely useful to the target customer.
5. Every listing must truthfully match the shipped file: format, number of resources, editability, features, screenshots, claims, and current official requirements.
6. Product SEO is a two-layer funnel:
   - **Payhip blog / product content** targets high-commercial-intent and product-adjacent searches.
   - **Apex / YouSafe estate content** owns deeper authority and informational coverage.
   - Both layers interlink naturally to the YouSafe file shop, the exact Payhip product, related articles, and relevant higher-value services without keyword cannibalization.
7. Unsupported trust claims such as `FIELD TESTED`, `READY TO USE`, or outcome-adjacent immigration claims must not ship until the underlying product has passed QA.

## Required QA gates per product

A product can move to `READY` only after all gates pass:

- Actual Payhip download retrieved.
- Archive opened, if applicable.
- Every shipped file opened.
- File format is suitable for the promised use case.
- Content is complete, readable, editable/printable where promised, and free of placeholder/source-only material.
- Formulas, hyperlinks, fillable fields, page navigation, or other functional features are tested where claimed.
- Product description matches the exact shipped artifact.
- Cover/preview imagery represents the real product.
- Category and tags are selected for buyer discovery, not generic stuffing.
- Current official requirements are checked for regulated/high-stakes products.
- Price/value positioning is reviewed against current competitors.
- Payhip SEO/blog keyword cluster is approved.
- Apex authority article / supporting cluster is approved.
- Product, Payhip blog, Apex article, and related products are interlinked.
- CTA hierarchy and next-step path are clear.
